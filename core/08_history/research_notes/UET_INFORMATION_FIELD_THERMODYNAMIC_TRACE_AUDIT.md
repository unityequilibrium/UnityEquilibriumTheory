# UET Information Field Thermodynamic-Trace Audit

**Status:** concept-definition audit. This file records a conservative interpretation of `I`
before further equation or engine work. It does not claim that the interpretation is proven.

## Why This Exists

Recent reconstruction work showed that the project already uses `I` as an
information/entropy/stimulus field, but the human-facing physical picture is still easy to
misread as abstract or mystical. This report locks the safer interpretation:

> `I` is not a ghost field, hidden matrix, or separate substance. It is a model variable for the
> physical trace left by change.

## Working Interpretation

The current conservative interpretation should be:

```text
I(x,t) = a thermodynamic-information trace field:
         a local record of disorder/order change, heat/entropy production,
         information loss or structural memory generated by changes in C(x,t).
```

In plain language:

- `C` is the more directly material/order side: mass, density, matter state, phase order, or
  other observable structure.
- `I` is the trace of how that structure has changed: entropy production, heat dissipation,
  thermal memory, stimulus, or hidden structural complexity.
- `I` can affect future `C` dynamics because the changed environment/trace changes the effective
  landscape in which `C` evolves.

## Infrared / Heat-Map Interpretation

Infrared should be treated as an **observable proxy**, not the universal definition of `I`.

| Layer | Conservative wording | Claim status |
| :-- | :-- | :-- |
| Concept | `I` records thermodynamic-information trace | model definition candidate |
| Physics proxy | heat, entropy production, dissipated work, thermal memory | plausible thermodynamic mapping |
| Observable example | infrared intensity / heat map | system-specific proxy only |
| Forbidden upgrade | `I is always infrared` | not supported |

Example:

```text
wood structure C burns
-> molecular order changes
-> heat, photons, smoke, entropy production, chemical redistribution appear
-> infrared heat pattern is one observable trace
-> UET may model that trace as I, if units and observables are declared
```

## Semi-Open Boundary Interpretation

UET should not frame systems as permanently open or permanently closed by default. The safer
interpretation is:

```text
systems are dynamically bounded:
their effective open/closed boundary depends on energy, entropy, information, and exchange flow.
```

This preserves ordinary thermodynamics:

- In a declared closed system, total entropy should not decrease.
- In an open or semi-open subsystem, local order can increase by exporting entropy elsewhere.
- UET's `J_in - J_out` lane is the natural place to represent boundary exchange.
- Strong claims about the universe as a whole need separate cosmology-level boundary arguments.

This should not be written as "Einstein assumes a closed universe and UET proves otherwise."
The safer wording is:

> UET asks whether many physical systems are better modeled as dynamically bounded
> thermodynamic-information systems rather than fixed closed boxes.

## Dynamic Equilibrium Interpretation

The project already has an A9 phrase: equilibrium is a dynamic center. This report interprets it
as:

```text
equilibrium is not a final static point;
it is a chosen reference condition under a declared boundary, scale, and observable.
```

Consequences:

- "Equilibrium" must state the boundary condition.
- A subsystem can look more ordered while the larger environment absorbs entropy.
- A verifier should say which balance it checks: local order, total entropy, exchange flux,
  energy cost, or information/thermal trace.
- A changing boundary can move the equilibrium reference itself.

## Equation Implications

The concept is compatible with the current candidate form:

```text
dI/dt = D_I nabla^2 I - m_I^2 I + source(C)
```

The source should be chosen by the physical mapping:

| Source form | Interpretation | Status |
| :-- | :-- | :-- |
| `beta C` | linear legacy source | legacy/simple bridge |
| `beta C^2` | aggregated structure generates stronger trace | current concept candidate |
| entropy-production term | heat/work/dissipation-generated trace | stronger future candidate if units close |
| infrared intensity | observable proxy for some thermodynamic systems | not universal |

For topic 0.11 and other spatial topics, `I` should propagate in the same spatial dimension as
the system being modeled. Otherwise `I` remains a local source/decay term rather than a spatial
trace field.

## Open Questions For Research

- Which measurable proxy is used for `I` in each topic: entropy production, heat flux,
  infrared intensity, structure factor, or another observable?
- What units does `I` carry in that topic: dimensionless proxy, J/K, W/m^2, bits, or normalized
  field units?
- Does the verifier track total entropy/export, or only local order?
- Where is the boundary: closed system, open subsystem, or dynamic/semi-open boundary?
- Does `I` merely record change, or does it feed back into the operator that controls `C`?

## Claim Boundary

Allowed wording:

> `I` is currently best treated as a thermodynamic-information trace field. Infrared or heat-map
> measurements may serve as observables for `I` in thermodynamic systems, but the repository has
> not proven a universal identification of `I` with infrared radiation.

Not allowed:

- `I is infrared` as a universal definition.
- `UET proves entropy can decrease in a closed system`.
- `UET overturns Einstein/GR`.
- `dynamic equilibrium is solved physics`.

## New operator-mode distinction

The audit above describes the repository's legacy I terminology. The opt-in
spacetime_trace_v1 lane narrows it further:

- C remains the material/structural state.
- sigma_C is the non-negative source made from change in C.
- I_trace is a retarded functional of source_history, not an independent field
  or a new substance.
- The history buffer is a computational cache, not a second ontology.
- Infrared and heat-map values remain system-specific observable proxies.

The legacy propagator and information-coupling modes remain available for
compatibility, but they must not be used as evidence that the new trace
functional has been derived or externally validated.
