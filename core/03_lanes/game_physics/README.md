## 1. คำถาม

หลักของ UET (burn law dF/dt = −P, แรงเสียดทานกับแรงสุ่มจากระบบปิดของชั้น 2, การอนุรักษ์ของ Noether) ช่วยให้ฟิสิกส์ในเกมใช้พลังคำนวณน้อยลงโดยยังถูกต้องได้ไหม เกณฑ์ที่ผู้เขียนตั้งไว้: คำนวณเร็วขึ้น ง่ายขึ้น ลดความซับซ้อน ไม่จำเป็นต้องเป็นของใหม่ แต่ต้องบอกได้ว่ามีข้อดีอะไร

## 2. วงการทำอย่างไรอยู่แล้ว (field map)

- **ส่วนที่แพง:** การหาการชน (broadphase, narrowphase) และตัวแก้ข้อจำกัด (constraint solver) โดยเฉพาะฉากที่ชนกันถี่
- **วิธีประหยัดที่มีอยู่:**
  - sleeping: PhysX และ Unity ใช้ "พลังงานจลน์ต่อมวลต่ำกว่าเกณฑ์ช่วงหนึ่ง"
  - island, simulation LOD, XPBD substepping (Macklin และคณะ)
  - multirate และ adaptive time stepping
  - Langevin coarse-graining: ใช้มากใน molecular dynamics แต่ในเกมยังใช้น้อย

| หลักของ UET | ใช้ในเกม | วงการมีแล้ว? |
|---|---|---|
| ชั้น 2: แรงเสียดทาน + แรงสุ่มจากระบบปิด | แทนเศษวัตถุจำนวนมากด้วยแรงเฉลี่ย | มีในงานวิทยาศาสตร์ |
| burn law: τ = ∫dE/P | ทำนายเวลาและจุดหยุดล่วงหน้า แล้วให้วัตถุหลับทันที | บางส่วน (sleep แบบใช้พลังงาน) |
| สิ่งที่เห็นคืออดีต: error = อัตราเปลี่ยน × อายุ | อัปเดตแต่ละวัตถุตามงบความคลาดเคลื่อน | มี (multirate, relevancy) ยังไม่ได้ทดสอบใน lane นี้ |
| ชั้น 3: สิ่งที่อยู่นานถูกเห็นมาก | แบ่งพลังคำนวณตามอายุของวัตถุ | มี (particle LOD) ยังไม่ได้ทดสอบ |

## 3. ผล A: แทนเศษวัตถุ 2,000 ชิ้นด้วยแรงเฉลี่ย ([`debris_bath.py`](debris_bath.py))

**ฉาก:** จานหนัก (M = 200) ถูกเตะให้วิ่งผ่านเศษวัตถุเบา 2,000 ชิ้นในกล่อง 2 มิติแบบ periodic เศษวัตถุไม่ชนกันเอง

**แบบจำลองย่อ** ใช้กฎสามข้อ ไม่ calibrate ค่าใดเลย:
1. แรงลากที่ขึ้นกับความเร็ว derive จากทฤษฎีจลน์ ร่วมกับแรงสุ่มตาม fluctuation-dissipation
2. บัญชีพลังงาน: ส่วนที่วัตถุเสียไปทำให้เศษวัตถุร้อนขึ้น
3. บัญชีโมเมนตัม: เศษวัตถุเคลื่อนตามโมเมนตัมที่ได้รับ

**สูตรแรงลากเทียบการจำลองเต็มที่ความเร็วคงที่ (ไม่ calibrate):**

| V | จำลองเต็ม | สูตร |
|---|---|---|
| 0.5 | −13.7 ± 2.1 | −12.9 |
| 1.0 | −26.8 ± 3.4 | −28.1 |
| 2.0 | −76.1 ± 4.6 | −71.9 |
| 3.0 | −142.1 ± 3.9 | −139.4 |

**การเคลื่อนที่ของจานหนัก (เทียบการจำลองเต็ม 16 รอบ):**

| ความเร็วตอนเตะ | ผิด (แบบจำลองย่อ) | ผิด (แรงเสียดทานเชิงเส้นอย่างเดียว) | การสุ่มของการจำลองเต็มเอง | ⟨V²⟩ ช่วงท้าย: เต็ม / ย่อ / สมดุลทฤษฎี |
|---|---|---|---|---|
| 0.25 | 6.9% | 9.3% | 7.0% | 0.0132 / 0.0099 / 0.0105 |
| 1.0 | **2.9%** | 7.2% | 1.5% | 0.0213 / 0.0190 / 0.0187 |
| 2.0 | **1.9%** | 8.0% | 1.0% | 0.0581 / 0.0466 / 0.0449 |
| 3.0 | **2.8%** | 9.7% | 0.7% | 0.1476 / 0.0914 / 0.0885 |

- **งานต่อขั้น:** การจำลองเต็มอัปเดต 2,000 ชิ้น แบบจำลองย่ออัปเดต 1 ชิ้น
- **เวลาจริงใน Python:** เร็วขึ้น 5–6 เท่า ถูกจำกัดด้วยลูปทีละขั้นของแบบจำลองย่อ ยังไม่ได้วัดในโค้ด engine จริง
- **⟨V²⟩ ช่วงท้ายที่ความเร็วเตะ 3:** การจำลองเต็มยังสูงกว่าสมดุลทฤษฎี 1.7 เท่า ข้อนี้เป็นข้อจำกัดของตัวจำลองเต็มเอง เพราะเศษวัตถุไม่ชนกันจึงกลับเข้าสมดุลไม่ได้ ไม่ใช่ข้อผิดของแบบจำลองย่อ แต่ยังไม่ได้ทดสอบกับเศษวัตถุที่ชนกันเอง

## 4. ผล B: งบพลังงานสำหรับการ sleep ([`energy_budget.py`](energy_budget.py))

**ฉาก:** ระเบิดเศษวัตถุ 300 ชิ้น ไถลบนพื้นที่มีแรงเสียดทานแบบ Coulomb และชนกันเอง

**กฎ:** วัตถุไปได้อีกไม่เกิน d = v²/(2μg) ถ้าวงระยะนี้ไม่ทับกับวงของวัตถุอื่น จะไม่มีการชนอีกแน่นอน จึงย้ายไปจุดหยุดแล้วให้หลับทันที กฎนี้แม่นตรงตามกฎแรงเสียดทาน

**เทียบกับ:** การ sleep แบบ engine ทั่วไป (ความเร็วต่ำกว่า 0.05 นาน 0.5 วินาที) ทั้งสองแบบใช้ grid broadphase ตัวเดียวกัน และตรวจวงระยะทุก 4 เฟรม

| seed | อัปเดตวัตถุ (มาตรฐาน → งบพลังงาน) | ทดสอบคู่ชน | งานรวม | เวลาจริง | ฉากนิ่งเมื่อ (วินาที) | ผิดจากแบบอ้างอิง (m) |
|---|---|---|---|---|---|---|
| 1 | 48,569 → 29,849 | 73,302 → 75,044 | **−14%** | −12% | 2.05 → 1.58 | 0.318 / 0.318 |
| 2 | 48,225 → 29,968 | 79,866 → 78,729 | **−15%** | −3% | 2.08 → 1.38 | 0.306 / 0.306 |
| 3 | 46,960 → 28,262 | 79,325 → 78,436 | **−16%** | −1% | 2.02 → 1.35 | 0.375 / 0.375 |

- ความคลาดเคลื่อนเท่ากับแบบมาตรฐานทุก seed ตัวเลข 0.3 m มาจากการชนแบบ chaotic ที่ไวต่อขนาดขั้นเวลา ซึ่งเกิดกับทั้งสองแบบเท่ากัน
- ถ้าตรวจวงระยะทุกเฟรม ต้นทุนการตรวจจะกินส่วนที่ประหยัดได้หมด ใน scratchpad ทดลองแล้วได้งานรวมเพิ่มขึ้น 2–4%

## 5. สรุป (AI interpretation)

- **ข้อดีที่วัดได้:**
  - **ผล A:** งานลดลง 2,000 เท่าต่อขั้น ผิดราว 2–3% และไม่ต้องปรับค่าเอง
  - **ผล B:** งานรวมลดลงราว 15% ฉากหลับเร็วขึ้นราว 30% และไม่เพิ่มความคลาดเคลื่อน
- **สิ่งที่ UET ให้:** กรอบเดียวที่บอกว่าแบบจำลองย่อต้องทำบัญชีอะไรบ้าง (พลังงาน, โมเมนตัม, burn law) และนำไปสู่กฎที่ไม่ต้องจูน ตัวเทคนิคเองไม่ใช่ของใหม่ (Langevin coarse-graining, sleep แบบใช้พลังงาน)
- **ยังไม่ได้ทดสอบ:**
  - เศษวัตถุที่ชนกันเอง
  - รูปทรงอื่นนอกจากจาน และงาน 3 มิติ
  - เวลาจริงในโค้ด engine (C++ หรือ GPU)
  - กฎงบความคลาดเคลื่อนสำหรับ multirate
