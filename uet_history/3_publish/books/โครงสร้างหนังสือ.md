# โครงสร้างหนังสือ: Local Writing Pattern

> **สถานะ:** มาตรฐานแม่แบบการเขียนระดับหน่วย (Writing Unit) สำหรับหนังสือในระบบนี้
>
> **ขอบเขต:** ควบคุมจังหวะการเล่า รูปแบบหัวข้อ และผิวหน้าการอ้างอิงของหน่วยเขียน
>
> **ไม่ใช่:** แผน Section, Book Blueprint, Literature Review, Claim Map หรือสถานะ W00–W18

## 1. ใช้ไฟล์นี้เมื่อไร

ไฟล์นี้ใช้หลังจากมีแผน Section/Book ที่อนุมัติแล้ว และ Book Blueprint ระบุ
`unit_id` ที่จะทำอย่างชัดเจน

- ถ้ายังไม่มี Section Plan, Book Plan หรือ Blueprint Lock ให้ทำ planning package ตาม [BOOK_WORKFLOW.md](../../BOOK_WORKFLOW.md) ก่อน
- ห้ามเริ่มงานด้วยการถามผู้เขียนว่า “จะเขียนตอนที่เท่าไร”
- Agent ต้องอ่าน manifest และ Blueprint แล้วเสนอ `unit_id` ที่เป็นหน่วยถัดไปตามสถานะจริง
- ชื่อภายในของหน่วยอาจเป็นบท ตอน หรือ section ได้ แต่ต้องมี `unit_id` เดียวและไม่เปลี่ยนเอง
- หนังสือสายนี้ใช้โครงสร้าง 8 ฟังก์ชันเป็นค่าเริ่มต้น การยกเว้นต้องบันทึกใน Book Blueprint และได้รับการอนุมัติจากผู้เขียน

## 2. ความสัมพันธ์กับระบบควบคุมงาน

| ระดับ | สิ่งที่ควบคุม | เอกสาร/สถานะหลัก |
| :-- | :-- | :-- |
| Section | แกนของ 3 เล่ม บทบาท การแบ่ง ownership ความต่อเนื่อง และ handoff | `SECTION_BLUEPRINT.md`, `S00–S09` |
| Book | สัญญาของเล่ม งานวิจัย แหล่งอ้างอิง claims และเวอร์ชันต้นฉบับ | `book_blueprint`, `BOOK_MANIFEST.json`, `W00–W18` |
| Writing Unit | วิธีเล่าเนื้อหาในหน่วยนั้นและจังหวะ A/B/C | ไฟล์นี้ + `unit_id` ที่อนุมัติแล้ว |

โครงสร้าง 8 ฟังก์ชันเป็นแม่แบบการผลิต ไม่ใช่ gate ใหม่ และไม่กำหนดจำนวนบท
หรือตอนของทุกเล่ม จำนวนและลำดับจริงต้องมาจาก Book Blueprint

## 3. Unit Execution Card ที่ต้องมี ก่อนเริ่มเขียน

ทุกหน่วยที่ถูกส่งให้เขียนต้องมีข้อมูลอย่างน้อย:

| ฟิลด์ | ความหมาย |
| :-- | :-- |
| `section_id` | Section แม่ ถ้ามี |
| `book_id` / `volume_number` | ตัวตนและลำดับของเล่ม |
| `unit_id` / `chapter_id` | รหัสหน่วยที่ stable |
| `purpose` | หน้าที่ของหน่วยต่อข้อเสนอของเล่ม |
| `reader_outcome` | เมื่ออ่านจบ ผู้อ่านต้องเข้าใจอะไร |
| `claim_ids` | claims ที่หน่วยนี้รับผิดชอบ |
| `source_ids` หรือ `source_tasks` | แหล่งที่ตรวจแล้วหรืองานค้นคว้าที่ต้องทำ |
| `counter_evidence` / `wording_boundary` | สิ่งที่ต้องระวังและระดับถ้อยคำที่ใช้ได้ |
| `handoff` | ความเชื่อมโยงไปยังหน่วยหรือเล่มถัดไป |
| `current_gate` / `blueprint_version` | สถานะและเวอร์ชันที่อนุญาตให้ทำงาน |

ถ้าการ์ดนี้ไม่ครบ ให้รายงานเป็น blocker หรือ source task ก่อน ไม่เริ่มเขียน
เนื้อหาเพื่อกลบช่องว่าง

## 4. โครงสร้าง 8 ฟังก์ชัน

หนึ่งหน่วยเขียนต้องร่างหัวข้อทั้ง 8 ตามลำดับนี้:

| ลำดับ | Function | หน้าที่ |
| :--: | :-- | :-- |
| 1 | **Recall & Connect** | เชื่อมกับสิ่งที่ผู้อ่านรู้หรือสิ่งที่มาก่อนหน้า |
| 2 | **Insight Hook** | เปิดคำถามหรือความขัดแย้งที่ทำให้ต้องอ่านต่อ |
| 3 | **Core Focus** | ระบุแก่นของหน่วยนี้ให้ชัด |
| 4 | **Relational Mechanism** | อธิบายกลไกและความสัมพันธ์ขององค์ประกอบ |
| 5 | **Everyday Application** | แปลงแนวคิดเป็นภาพหรือสถานการณ์ที่เข้าใจได้ |
| 6 | **Systemic Impact** | สังเคราะห์ผลกระทบต่อระบบหรือชีวิต |
| 7 | **Forward Bridge** | เชื่อมไปยังหน่วยหรือคำถามถัดไป |
| 8 | **Research Reference** | แสดงงานวิจัย/หลักฐานตามรูปแบบที่กำหนด |

### การแบ่ง A/B/C

ถ้า Book Blueprint ของเล่มใช้การแบ่ง A/B/C ให้จัดดังนี้:

| ส่วน | ฟังก์ชัน |
| :-- | :-- |
| A | 1. Recall & Connect, 2. Insight Hook, 3. Core Focus |
| B | 4. Relational Mechanism, 5. Everyday Application |
| C | 6. Systemic Impact, 7. Forward Bridge, 8. Research Reference |

A/B/C คือการจัดจังหวะหรือเลย์เอาต์ ไม่ใช่จำนวนหน้าตายตัว และไม่ใช่ gate
การแบ่งต้องเกิดหลังร่างครบและผ่านการ review เนื้อหาแล้ว

## 5. ลำดับการทำงานระดับหน่วย

```text
approved unit_id
  -> source and claim task
  -> ร่างครบ 8 ฟังก์ชันตามลำดับ
  -> ผู้เขียนตรวจความหมาย น้ำเสียง และเจตนา
  -> แก้เป็น draft ที่ได้รับการยอมรับ
  -> แบ่ง A/B/C เมื่อพร้อม
  -> ตรวจ W09 และ W10 ตาม gate ของเล่ม
```

กติกาในแต่ละช่วง:

1. **ก่อนร่าง:** อ่าน Unit Execution Card และตรวจ source/claim boundary
2. **ร่างครั้งแรก:** เขียนครบทั้ง 8 ฟังก์ชันก่อน อย่าแบ่งหน้าเพื่อซ่อนเนื้อหาที่ยังไม่ครบ
3. **Reference:** ใช้ source ที่อยู่ในสถานะเหมาะสมจาก Source Register เท่านั้น แหล่งที่วางแผนไว้ยังไม่ใช่ citation ที่ตรวจแล้ว
4. **Author review:** ผู้เขียนเป็นผู้ตัดสินความหมาย น้ำเสียง ความตั้งใจ และการรับข้อเสนอของเล่ม
5. **แบ่ง A/B/C:** ทำหลัง review ไม่เพิ่ม claim ใหม่ในขั้นจัดหน้า
6. **ตรวจท้ายรอบ:** เมื่อแก้ต้นฉบับจริง ให้ใช้ W09 สำหรับความครบถ้วน/การเปลี่ยนแปลง และ W10 สำหรับ fact/citation ตามที่ gate กำหนด

Literature Review เป็นงานระดับ Section/Book ใน W03 หรือ S03 ก่อน Blueprint
Lock ไม่ใช่สิ่งที่ต้องเขียนซ้ำเต็มชุดในทุกหน่วย แต่หน่วยยังต้องมี source task
และตรวจ claim ที่ตัวเองรับผิดชอบ

## 6. รูปแบบหัวข้อและชื่อภาษาไทย

- ระหว่างร่าง ใช้ `English Function + ชื่อไทยที่อธิบายแก่นเนื้อหา`
- ชื่อไทยต้องเป็น keyword ที่สื่อความหมาย ไม่ใช่คำแปลตรงตัวเสมอไป
- ตอนจัดรูปเล่มจริง ใช้ชื่อไทยเป็นหลัก และซ่อน label ภาษาอังกฤษได้
- ห้ามเปลี่ยนชื่อบท หน่วย หรือรหัสจาก Blueprint เอง

## 7. รูปแบบ Research Reference

ในเนื้อหาที่ผ่านการตรวจแล้ว ให้ใช้รูปแบบนี้เท่านั้น:

📚 **งานวิจัยที่สนับสนุน**
- (ชื่องานวิจัยและปี)
> (ประเด็นของงานวิจัย)

ห้ามทำให้ source ที่ยังเป็นเพียง planned หรือ lead ดูเหมือนเป็น citation ที่
verified แล้ว หากยังไม่มีหลักฐานที่ตรวจได้ ให้เขียนว่า “ยังไม่พบงานวิจัยที่
เกี่ยวข้อง” หรือเปิดเป็น source task ตามที่ระบุใน Unit Execution Card และ
Source Register

แหล่งอ้างอิงสำหรับผู้อ่านอาจสั้นได้ แต่ข้อมูลภายในต้องย้อนกลับไปหา
`source_id`, locator, ข้อจำกัด และสถานะการตรวจสอบได้

## 8. ภาษากับน้ำเสียง

- ใช้ “ผม–คุณ” เป็นหลัก
- ใช้ “กู–มึง” ได้เฉพาะจังหวะที่ผู้เขียนอนุมัติและมีหน้าที่ทางอารมณ์ชัดเจน
- ภาษาเข้าใจง่าย จริงใจ ตรงประเด็น ไม่ทำให้ข้อสรุปดูหนักแน่นเกินหลักฐาน
- ใช้อิโมจิได้เมื่อเป็นส่วนหนึ่งของสไตล์เล่ม แต่ไม่ใช้แทนหลักฐานหรือคำอธิบาย
- รักษาความไม่แน่นอน ข้อจำกัด และความแตกต่างระหว่าง fact, interpretation และ hypothesis

## 9. เกณฑ์ตรวจหน่วยก่อนส่งต่อ

- [ ] มี `unit_id` และ Unit Execution Card ที่ตรงกับ Blueprint
- [ ] ร่างครบ 8 ฟังก์ชันและเรียงลำดับถูกต้อง
- [ ] ชื่อไทยอธิบายเนื้อหาจริง ไม่ใช่คำแปลลอย ๆ
- [ ] ทุก claim สำคัญมี claim ID และ source task/source ID
- [ ] แยก source ที่วางแผนไว้จาก source ที่ตรวจแล้ว
- [ ] มี counter-evidence หรือระบุว่าไม่พบ/ยังต้องค้นหา
- [ ] ใช้ถ้อยคำไม่เกิน evidence boundary
- [ ] ผ่าน author review ก่อนแบ่ง A/B/C
- [ ] การแก้ต้นฉบับมีขอบเขตและจะถูกบันทึกใน W09/UPDATE_LOG เมื่อถึง gate

## 10. ข้อห้าม

- ห้ามเริ่มจากการเลือกตอนแบบสุ่มนอก Blueprint
- ห้ามสร้างบท หน่วย หรือ claim ใหม่โดยไม่อัปเดตแผนที่เกี่ยวข้อง
- ห้ามใช้ bibliography ที่ยังไม่ประเมินเป็นหลักฐานยืนยัน
- ห้ามเพิ่ม claim ระหว่างการแบ่งหน้าโดยไม่ส่งกลับไปตรวจ source/claim
- ห้ามเปลี่ยนสถานะ gate เพียงเพราะร่างยาวขึ้นหรือมีไฟล์เพิ่ม
- ห้ามลบ รวม ย้าย หรือเขียนทับต้นฉบับเดิมโดยไม่ระบุขอบเขตและตรวจ W09
- หากไม่พบหลักฐาน ให้เปิดเป็น blocker/source task ไม่เติมคำตอบด้วยความมั่นใจ

ไฟล์นี้เป็นแม่แบบระดับหน่วยเท่านั้น กติกาการวางแผน Section/Book และสถานะ
การทำงานให้ยึด [BOOK_WORKFLOW.md](../../BOOK_WORKFLOW.md) เป็นหลัก
